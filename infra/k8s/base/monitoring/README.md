# monitoring/

Prometheus + Grafana (via the `prometheus-community/kube-prometheus-stack` Helm chart) for cluster and GPU metrics — added to investigate the recurring `gpu-node-01` GPU hang incidents (see `docs/decisions` and CLAUDE.md), specifically to graph temperature, VRAM utilization, and power draw over time while running test workloads (small ComfyUI video generations) and watching for anomalies before they hang the node.

This is the bigger addition `infra/gpu-node-01/gpu-temp-exporter/README.md` flagged and deferred — that service (Uptime Kuma JSON polling) stays for simple up/down threshold alerting; this stack is for actual time-series graphs.

## What's deployed

- **kube-prometheus-stack**: Prometheus, Grafana, Alertmanager, `node-exporter` (DaemonSet, both nodes), `kube-state-metrics` — the standard bundle. Prometheus/Grafana/Alertmanager/the operator are pinned to `control-plane-01` via `nodeSelector` (see `values.yaml`) so they never compete with `gpu-node-01`'s single-GPU Ollama/ComfyUI toggle for CPU/RAM.
- **`nvidia_gpu_exporter`**: runs as a **systemd service directly on `gpu-node-01`**, not a k8s workload — see `infra/gpu-node-01/nvidia-gpu-exporter/README.md` for why (device-plugin GPU-resource contention). Prometheus scrapes it as a static target (`192.168.0.79:9835`), configured in `values.yaml`'s `additionalScrapeConfigs`.
- **Storage**: Prometheus gets a 20Gi `local-path` PVC, 15-day retention. Grafana gets a 2Gi `local-path` PVC so dashboards/datasources survive pod restarts.
- **Exposure**: Grafana via NodePort `30300` (matching the existing NodePort-everywhere pattern — see `docs/decisions/0009`). Prometheus/Alertmanager are not exposed externally; use `kubectl port-forward` if you need direct access.

## Deploy

Prerequisite: Helm on `control-plane-01` — `cd ~/homelab && git pull && bash infra/bootstrap/install-helm.sh`.

```bash
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm repo update
helm install prometheus prometheus-community/kube-prometheus-stack \
  -n monitoring --create-namespace \
  -f infra/k8s/base/monitoring/values.yaml
```

Then deploy the GPU exporter on `gpu-node-01` per `infra/gpu-node-01/nvidia-gpu-exporter/README.md`.

## Access Grafana

`http://192.168.0.47:30300` — username `admin`, password auto-generated by the chart (**intentionally not committed to this public repo**):

```bash
kubectl get secret prometheus-grafana -n monitoring -o jsonpath="{.data.admin-password}" | base64 -d
```

Import dashboard ID `14574` ("Nvidia GPU Metrics") for the GPU exporter's temp/VRAM/power panels — see `infra/gpu-node-01/nvidia-gpu-exporter/README.md`.

## Why kube-prometheus-stack instead of hand-rolled manifests

It's the de facto standard Helm chart for this exact bundle (Prometheus Operator + Grafana + Alertmanager + node-exporter + kube-state-metrics, pre-wired together with sane defaults and CRDs for `ServiceMonitor`/`PrometheusRule`), and it's the natural vehicle for `additionalScrapeConfigs` when a target (like the host-level GPU exporter here) can't be a `ServiceMonitor`. Hand-rolling this from scratch would mean re-implementing a lot of well-trodden wiring for no benefit.
